# 空岛RPG通行证：Mod端代码绘制UI方案 v0.2

> 当前用途：替代原“Mod端图片素材清单与生成Prompt”。
> 新方向：不再依赖自定义生成图片，通行证界面主体改为 Minecraft Forge 客户端代码绘制。
> 目标：在 Minecraft 原版 GUI 与 Forge 渲染能力范围内，用矩形、渐变、斜切角、多层描边、物品图标、几何符号、扫描线、进度条和轻量粒子做出较美观的工业科幻界面。
> 适配原则：优先兼容 Forge 常规 Screen 渲染能力，不依赖复杂 Shader，不依赖 SVG，不依赖大量图片，不强行做网页式 UI。
> 2026-09-23 范围调整：赛季归档只在服务端插件留档与管理，不在客户端 Mod 请求或展示；左侧导航不再包含归档。可交互按钮应有悬停高光，切换左侧标签使用渐变过渡。

---

## 1. 总体设计原则

原方案中的 AI 生成背景图、卡框图、按钮图、徽章图、粒子图、伙伴立绘等自定义素材，全部改为代码绘制或 Minecraft 原生资源替代。

新的 UI 方向为：

> **代码绘制的工业战术终端 UI。**

视觉关键词：

```text
黑灰底色
黄色警示线
青蓝数据光
半透明面板
斜切角卡片
圆形雷达
细线网格
Minecraft 原生物品图标
低成本微动效
```

核心原则：

1. **不使用自定义生成图片作为界面主体。**
2. **奖励图标优先使用 Minecraft 原版物品图标。**
3. **特殊图标用代码绘制简单几何符号。**
4. **所有面板、按钮、卡框、进度条、遮罩、锁标、角标都用代码绘制。**
5. **动画只做轻量效果，例如呼吸描边、扫描线、进度条平滑、粒子点扩散。**
6. **不使用高成本模糊、复杂后处理、动态 Shader、大面积半透明叠层。**
7. **所有 UI 必须能适配不同 GUI Scale 和窗口尺寸。**

## 2. Minecraft 与 Forge 限制考虑

### 2.1 不按网页 UI 思路设计

Forge UI 不是 HTML 页面，没有 CSS、Flex、SVG、Canvas API，也不适合做大量自由矢量曲线。

因此不要设计这些内容：

| 不建议          | 原因                  |
| ------------ | ------------------- |
| SVG 图标系统     | Minecraft GUI 不直接支持 |
| CSS 式布局      | 需要自己写布局计算           |
| 大量圆角抗锯齿      | 原版 GUI 绘制不适合        |
| 高斯模糊背景       | 成本高，兼容性差            |
| 复杂 Shader 动效 | 维护困难，低配风险高          |
| 大量全屏透明叠层     | 容易影响帧率              |
| 每帧大量 new 对象  | 容易造成 GC 抖动          |
| 每个按钮都独立纹理    | 资源多，维护麻烦            |

推荐做这些：

| 推荐             | 原因           |
| -------------- | ------------ |
| 矩形和渐变矩形        | 最稳定          |
| 多层描边           | 成本低，效果明显     |
| 斜切角面板          | 科幻感强，易绘制     |
| Minecraft 物品图标 | 原版风格统一       |
| 简单几何图标         | 可代码绘制        |
| 少量粒子点          | 成本可控         |
| 扫描线和进度条        | 好看且易实现       |
| 固定布局 + 自适应缩放   | 适配 GUI Scale |

## 5. 基础绘制组件

### 5.1 斜切角面板

斜切角面板是本 UI 的核心形状。

用途：

* 主面板
* 奖励卡
* 任务卡
* 导航按钮
* 购买弹窗
* 提示框
* 右侧关键奖励栏

推荐绘制方式：

```text
1. 先画主体中间矩形
2. 再画左右矩形补齐
3. 四角用小三角形或阶梯像素近似斜切
4. 外层画暗色边
5. 内层画主题色细边
6. 左上或顶部加一条黄色警示线
```

为了兼容，斜切角不必追求完美抗锯齿。Minecraft 像素风下，利落的硬边反而更统一。

参数建议：

| 参数    |       建议值 |
| ----- | --------: |
| 斜切角大小 | 8 到 16 px |
| 外描边   |      1 px |
| 内描边   |      1 px |
| 面板透明度 | 200 到 235 |
| 高亮线宽度 |      2 px |
| 阴影偏移  |  2 到 4 px |

---

### 5.2 多层描边奖励卡

奖励卡不使用图片卡框，全部代码绘制。

每张奖励卡包含：

```text
外层阴影
稀有度外框
半透明卡片底
顶部等级标签
中央物品图标
底部数量文字
状态遮罩
领取状态符号
```

不同奖励线样式：

| 奖励线 | 卡框样式              |
| --- | ----------------- |
| 免费线 | 灰蓝描边，低亮度          |
| 进阶线 | 黄色描边，左上角亮边        |
| 典藏线 | 金色外框，青蓝内光，顶部小三角装饰 |

不同状态：

| 状态    | 绘制效果            |
| ----- | --------------- |
| 未解锁   | 半透明黑遮罩 + 锁形几何图标 |
| 可领取   | 黄色呼吸描边          |
| 已领取   | 绿色对勾 + 降低亮度     |
| 当前等级  | 青蓝外框闪烁          |
| 高价值奖励 | 金色扫光线           |

### 5.3 任务卡

任务卡采用横向斜切面板。

结构：

```text
[六边形图标槽] 任务标题                         +500 EXP
              任务描述
              [========----------]  6 / 10
```

绘制组成：

| 元素    | 绘制方式          |
| ----- | ------------- |
| 背景    | 半透明斜切矩形       |
| 左侧图标槽 | 六边形或斜切小框      |
| 标题    | 原版字体绘制        |
| 描述    | 原版字体绘制，限制宽度换行 |
| 经验奖励  | 黄色文字          |
| 进度条底  | 深灰矩形          |
| 进度条填充 | 黄色或青蓝矩形       |
| 完成状态  | 绿色描边          |
| 可领取状态 | 黄色呼吸边         |

注意：任务卡不要太高，Minecraft 屏幕空间很珍贵。建议一屏显示 5 到 7 条。

---

### 5.4 按钮

按钮不使用贴图，全部绘制。

按钮类型：

| 类型    | 样式          |
| ----- | ----------- |
| 普通按钮  | 深灰底 + 黄色细描边 |
| 主操作按钮 | 黄色填充 + 深色文字 |
| 次级按钮  | 深灰底 + 青蓝描边  |
| 危险按钮  | 深红底 + 红色描边  |
| 禁用按钮  | 灰色低透明度      |

按钮状态：

| 状态       | 表现             |
| -------- | -------------- |
| Normal   | 普通描边           |
| Hover    | 描边变亮，背景稍亮      |
| Pressed  | 背景变暗，文字下移 1 px |
| Disabled | 透明度降低，文字变灰     |

命中区域建议仍使用矩形，不要真的按斜切区域做复杂碰撞。视觉是斜切，点击区域可以是外接矩形，减少输入判断复杂度。

---

### 5.5 圆形雷达

首页中央不再依赖伙伴立绘，改为代码绘制“赛季雷达核心”。

构成：

* 多层圆环
* 旋转扫描线
* 放射刻度
* 中央赛季符号
* 周围剧情节点
* 节点连线
* 当前节点高亮

由于 Minecraft GUI 不适合高精度矢量圆，圆环可以用短线段近似。

性能建议：

| 项目   | 建议                               |
| ---- | -------------------------------- |
| 圆环线段 | 32 到 64 段                        |
| 低配模式 | 24 到 32 段                        |
| 扫描线  | 三角扇形或细线旋转                        |
| 节点数量 | 3 到 8 个                          |
| 动画频率 | 根据 tick 或 partialTicks 计算，不创建新对象 |

节点样式：

| 节点类型   | 形状      | 颜色  |
| ------ | ------- | --- |
| 主线节点   | 六边形     | 青蓝  |
| 奖励节点   | 菱形      | 黄色  |
| Boss节点 | 三角形     | 红橙  |
| 已完成节点  | 圆点 + 对勾 | 绿色  |
| 未解锁节点  | 空心圆     | 灰色  |
| 当前节点   | 外圈呼吸描边  | 主题色 |

---

### 5.6 简单几何图标

特殊图标不画贴图，用代码绘制。

| 图标   | 绘制方式          |
| ---- | ------------- |
| 赛季币  | 圆形 + 内部裂隙折线   |
| 伙伴碎片 | 不规则菱形 + 发光边   |
| 芯片   | 小矩形 + 电路线     |
| 锁    | 矩形锁体 + 半圆锁扣近似 |
| 领取   | 圆形 + 对勾线      |
| 警告   | 三角形 + 竖线      |
| 航线   | 点线 + 小三角箭头    |
| 地表协防 | 盾形 + 十字线      |
| 工业   | 齿轮简化形，可用多边形近似 |

如果多边形绘制复杂，优先用矩形和线段组合。不要为了一个图标引入复杂渲染管线。

## 6. 页面布局

### 6.1 首页

首页承担赛季氛围、等级进度、关键奖励预览和导航入口。

布局：

```text
┌────────────────────────────────────────────┐
│ S1 故土回声       Lv.24   EXP 640/1000     │
│ 赛季币 1200       可领取 3                 │
├──────────┬─────────────────────┬───────────┤
│ 首页     │                     │ 关键奖励  │
│ 奖励     │       圆形雷达       │ Lv.10     │
│ 任务     │                     │ Lv.30     │
│ 伙伴     │      剧情节点        │ Lv.50     │
│ 赛季币   │                     │ Lv.80     │
└──────────┴─────────────────────┴───────────┘
```

代码绘制重点：

* 顶部状态栏为半透明深色长条。
* 左侧导航为斜切按钮列表。
* 中央为圆形雷达，不放大图背景。
* 右侧为关键奖励卡片。
* 背景为深色渐变 + 细网格 + 少量漂浮粒子。

---

### 6.2 奖励轨道页

奖励页采用横向轨道。

```text
Lv     1     2     3     4     5     6     7
免费   □────□────□────□────□────□────□
进阶   ◆────◆────◆────◆────◆────◆────◆
典藏   ◈────◈────◈────◈────◈────◈────◈
```

绘制规则：

| 元素   | 绘制方式        |
| ---- | ----------- |
| 等级数字 | 原版字体        |
| 轨道线  | 1 到 2 px 横线 |
| 奖励卡  | 小型斜切卡       |
| 已领取  | 绿色对勾        |
| 可领取  | 黄色呼吸描边      |
| 未解锁  | 半透明遮罩 + 锁   |
| 当前等级 | 青蓝竖线或外框     |

滚动处理：

* 奖励等级较多时使用横向滚动。
* 只渲染屏幕内可见奖励卡，避免一次绘制全部 80 级。
* 鼠标滚轮可横向移动。
* 拖动滚动条可快速浏览。

### 6.3 任务页

任务页分为左侧分类和右侧列表。

分类：

* 每日任务
* 每周任务
* 赛季任务
* 主线关联
* 已完成

布局：

```text
┌──────────┬───────────────────────────────┐
│ 每日     │ 任务卡 1                       │
│ 每周     │ 任务卡 2                       │
│ 赛季     │ 任务卡 3                       │
│ 主线     │ 任务卡 4                       │
│ 已完成   │ 任务卡 5                       │
└──────────┴───────────────────────────────┘
```

适配限制：

* 任务列表使用滚动裁剪。
* 文本过长时省略或换行。
* Tooltip 显示完整描述。
* 每帧只渲染可见任务卡。

不使用购买背景图，改成代码绘制仪式感弹窗。

```text
左侧权益摘要
```

典藏弹窗增强：

## 8. 动效设计

动效应轻量、稳定、可关闭。

| 动效      | 用途        | 实现建议              |
| ------- | --------- | ----------------- |
| 呼吸描边    | 可领取奖励、主按钮 | alpha 随时间正弦变化     |
| 扫描线旋转   | 首页雷达      | 根据 tick 计算角度      |
| 节点闪烁    | 新解锁节点     | alpha 间歇变化        |
| 进度条平滑增长 | 经验、任务进度   | 当前显示值缓动到目标值       |
| 悬停高亮    | 按钮、奖励卡    | 背景和描边增亮           |
| 点击反馈    | 按钮        | 内容下移 1 px         |
| 粒子扩散    | 领取奖励      | 少量点扩散，生命周期短       |
| 扫光线     | 典藏奖励      | 一条斜线从左到右移动        |
| 页面滑入    | 切换页签      | 100 到 200 ms 轻微位移 |

性能限制：

1. 粒子数量建议小于 40。
2. 雷达线段建议小于 64。
3. 背景网格不要每格做复杂对象。
4. 动画只改变数值，不反复创建纹理或对象。
5. 提供 `lowPerformanceMode` 关闭粒子、扫光和高频闪烁。

## 11. Forge 端实现建议

### 11.1 Screen 层级

建议通行证主界面使用一个主 Screen。

```text
RayBattlePassScreen
├─ HomePage
├─ RewardTrackPage
├─ TaskPage
├─ PartnerPage
└─ PopupLayer
```

不要每个页面都开独立 Screen，避免状态管理变乱。

### 11.2 数据与渲染分离

建议拆成三层：

```text
数据层：PassViewData
布局层：PassLayout / Rect / Bounds
渲染层：GuiRenderKit
```

数据层只关心：

* 等级
* 经验
* 赛季币
* 奖励列表
* 任务列表
* 可领取数量
* 解锁状态
* 玩家当前档位

布局层只关心：

* 每块区域的位置和大小
* 滚动偏移
* 当前页签
* 鼠标悬停目标

渲染层只负责画：

* 面板
* 文字
* 物品
* 图标
* 进度条
* 动效

### 11.3 坐标适配

所有 UI 不要写死 1920x1080。

建议：

```text
screenWidth = 当前屏幕宽
screenHeight = 当前屏幕高

baseWidth = min(screenWidth - 40, 420 到 520 的比例扩展)
baseHeight = min(screenHeight - 40, 260 到 320 的比例扩展)

centerX = screenWidth / 2
centerY = screenHeight / 2
```

推荐最小适配：

| 项目        | 建议          |
| --------- | ----------- |
| 最小宽度      | 320 px      |
| 最小高度      | 240 px      |
| GUI Scale | 适配 2 到 4    |
| 文本过长      | 省略或 Tooltip |
| 列表过长      | 滚动裁剪        |
| 横向奖励轨道    | 只渲染可见部分     |

### 11.4 裁剪区域

任务列表、奖励轨道都需要裁剪。

注意：

* 裁剪区域要根据 GUI Scale 做换算。
* 开启裁剪后必须关闭。
* 不要嵌套太多裁剪层。
* Tooltip 建议在裁剪关闭后再绘制。

### 11.5 物品图标

奖励图标优先使用 `ItemStack` 渲染。

建议：

* 物品图标大小 16x16 或 24x24。
* 高价值卡可放大到 32x32，但不要过大。
* 数量文字放右下角。
* Tooltip 使用物品名和奖励说明，不直接复用复杂 NBT 文本。

## 12. 性能规范

### 12.1 每帧渲染注意

不要在 `render()` 中做这些事：

* 解析 YAML。
* 创建大量 List / Map / Rect 对象。
* 动态加载纹理。
* 进行复杂排序。
* 重新计算全部任务布局。
* 重新构造所有文字 Component。

建议：

* 数据收到时预处理。
* 页面切换时计算布局。
* render 只读取已计算好的 layout。
* 动画只用 tick 时间计算 alpha、offset、angle。
* 滚动列表只渲染可见项。

### 12.2 低配模式

提供低配模式：

```yaml
low-performance-mode:
  enabled: false
  disable-particles: true
  disable-sweep-light: true
  radar-segments: 24
  max-visible-particles: 10
  disable-background-grid-animation: true
```

低配模式下保留功能，不牺牲可读性，只减少装饰。

## 15. 最终结论

通行证 Mod 端 UI 不再走“生成图片堆界面”的路线，而是改成：

> **Forge 适配的代码绘制终端 UI。**

它的核心优势是：

* 更轻量。
* 更统一。
* 更适合 Minecraft 原版风格。
* 更容易适配 GUI Scale。
* 更容易维护多个赛季主题。
* 更少资源包压力。
* 更少版权和风格不稳定风险。
* 更适合长期运营。

一句话定稿：

> 通行证界面使用代码绘制的黑灰工业终端风格，通过斜切面板、多层描边、圆形雷达、原版物品图标、几何状态符号、轻量动效和主题色配置完成视觉表现，不再依赖自定义生成图片。

## 16. 小分辨率适配验收

实现采用自适应虚拟画布：

- 常规窗口最大画布为 `800x520`。
- 常见小窗口直接使用当前 GUI 尺寸重排，字体保持原生 `1:1` 像素渲染，避免非整数缩放导致文字模糊。
- 仅当 GUI 尺寸低于 Minecraft 常规最小值约 `300x220` 时，才对整体界面做兜底等比缩放。
- 宽度或高度不足时进入紧凑模式，右侧关键奖励栏默认收起，并以浮层方式展开。
- 右侧关键奖励栏在常规与紧凑模式下都使用固定宽度平移和裁剪动画，不能通过改变面板宽度制造跳变。
- 奖励和任务列表必须启用裁剪，不能覆盖顶部栏或底部提示。
- 购买、奖励详情和赛季结算弹窗必须限制在当前画布内。
- 伙伴页在矮窗口隐藏次要外观预览，保留伙伴核心信息。

最低回归矩阵：

| 窗口 | 预期 |
| --- | --- |
| 1920x1080 | 完整布局 |
| 1280x720 | 完整布局 |
| 854x480 | 完整布局，无弹窗越界 |
| 640x360 | 紧凑布局，右栏默认收起 |
| 480x270 | 等比缩放，全部按钮可点击 |
| 320x240 | 最小画布缩放，界面完整可见 |
| 480x854 | 竖屏紧凑布局 |
| 1024x300 | 矮屏紧凑布局 |
# SkyPixelQuest 隐藏任务交互（2026-09-23）

每日、每周和赛季的外部任务由服务端 RayBattlePass 从 SkyPixelQuest 读取目标进度。任务未完成时显示由服务端配置的“前往”按钮；完成后显示有悬停高光的“领取”，向服务端发送 `PASS_CLAIM_TASK`（只含任务 ID）。领取成功后的新快照将按钮更新为“已领取”。经验和物品仅由服务端在手动领取时发放，客户端不根据本地进度自行发奖。SkyPixelQuest 自身界面不展示这类任务。旧式任务沿用原显示语义。

## 2026-09-23 界面精简与交互补充

- 顶部沿界面宽度展示赛季等级经验进度；满级时同一进度条改为循环宝箱进度。
- 首页雷达圆环两侧是显眼的“查看奖励”“查看任务”入口，点击后沿用左侧标签渐变切换。
- 奖励轨道可滚轮或按住左键水平拖动；左键轻点奖励卡片打开详情，拖动不会误触详情，右键可领取。
- 左侧仅保留首页、奖励、任务；移除赛季币和伙伴页面，也不再自动请求伙伴页面数据。循环宝箱领取入口移至右侧栏。
- 任务分类仅保留每日、每周、赛季三个可点击的分段按钮；不再展示公会协作、限时任务、已追踪分类。外部任务由服务端按周期自动接取，完成后手动领取奖励。
- 右侧栏展开或滑动时会挡住下层内容的悬停、点击与滚轮命中，避免奖励卡片在栏后发亮。
